## 1. Кодирование решения — куда относится наша модель

Заметка [[Кодирование решений в генетических алгоритмах]] выделяет 4 вида кодирования: бинарное,
целочисленное, вещественное, **предметное** ("представление специально отражает структуру решения,
например перестановку в задаче маршрутизации"). Хромосома проекта (`H`-вектор, `i` встречается `pᵢ` раз) —
это предметное кодирование, родственное перестановочному, но не чистая перестановка (значения повторяются).

Требования к кодировке из конспекта — все три уже выполнены текущей моделью:
- однозначная интерпретация как решения — да: `xₜ=i` ⇒ квант `t` занят `Pᵢ`;
- эффективное вычисление приспособленности — да, `O(H)` проход для `Eᵢ`, затем `F(x)`;
- не порождать много недопустимых потомков — **это как раз слабое место наивного кроссовера**, см. §3.

## 2. Выбор родителей vs. отбор — терминологическая развилка для отчёта

Конспект чётко разделяет два разных этапа ([[Выбор родителей в генетическом алгоритме]] vs.
[[Отбор в генетических алгоритмах]]), которые в постановке задачи проекта фактически объединены в один шаг
("пропорциональный отбор... вероятность участия в скрещивании"). Стоит явно оговорить в отчёте, что проект
использует пропорциональный отбор **и** для выбора родителей, **и** как основной механизм формирования
следующего поколения — это осознанное упрощение классической схемы, а не пропуск.

Альтернативы для выбора родителей (панмиксия / инбридинг / аутбридинг) можно упомянуть как вариацию:
инбридинг (пара с ближайшей по расстоянию особью) ускоряет локальную сходимость, аутбридинг — усиливает
исследование. Для перестановочной хромосомы расстояние можно определить как число несовпадающих позиций
(аналог расстояния Хэмминга).

## 3. Кроссовер — почему нужен специальный оператор (подтверждение из лекции)

Конспект прямым текстом говорит: **"Для перестановок нужны специальные операторы, сохраняющие корректность
перестановки"** ([[Кроссовер и рекомбинация в генетических алгоритмах]]). Одно-/двухточечный кроссовер и
дискретная/промежуточная рекомбинация здесь неприменимы напрямую — это соответствует уже отмеченному в
`CLAUDE.md` и в `research_notes.md` (Bierwirth, GOX) выводу. Лекционный конспект не даёт готового
перестановочного оператора — GOX/repair-подход из `research_notes.md` остаётся источником для выбора
конкретного оператора.

## 4. Мутация — ключевая находка: готовые операторы для перестановок

Заметка [[Мутация и инверсия в генетических алгоритмах]] прямо перечисляет операторы мутации **по видам
кодирования**, включая нужный случай: *"для перестановки — обмен, вставка или разворот элементов с
сохранением допустимости"*. Это готовый список кандидатов для мутации в демо-программе:

- **обмен (swap):** поменять местами два случайных гена `xₜ₁ ↔ xₜ₂`. Инвариант "`i` встречается `pᵢ` раз"
  сохраняется автоматически — переставляются позиции существующих значений, набор значений не меняется.
- **вставка (insertion):** выдернуть ген из позиции `t₁` и вставить в позицию `t₂`, сдвинув остальные —
  тоже не меняет мультимножество значений, инвариант сохраняется.
- **разворот (inversion/reversal):** развернуть порядок генов на случайном отрезке `[t₁, t₂]` — тоже
  сохраняет мультимножество.

**Важно для проекта:** в отличие от кроссовера, для мутации в этой задаче можно не изобретать
специализированный оператор — swap/insertion/reversal над вектором `x` **тривиально допустимы** (не требуют
repair), поскольку они лишь переставляют позиции уже существующих генов, а не заменяют значения. Это стоит
явно зафиксировать как решение по мутации в `CLAUDE.md`, когда до этого дойдёт.

Отдельно — источник предупреждает о терминологической путанице: "инверсия" в лекции означает обмен местами
двух *частей* хромосомы целиком (что для нашей задачи эквивалентно частному случаю кроссовера/перестановки
блоков), а не разворот порядка генов внутри участка (это другой, более распространённый в литературе смысл
термина "инверсия" = reversal выше). В отчёте стоит явно оговорить, в каком смысле термин используется.

## 5. Отбор — конспект подтверждает и детализирует выбор проекта

[[Отбор в генетических алгоритмах]] описывает пропорциональный отбор (рулетка) — ровно механизм, уже
зафиксированный в модели проекта — и даёт две технические детали, которые можно упомянуть в отчёте как
"более аккуратные" реализации рулетки, если наивная рулетка (выбор `N` раз независимо, с возвращением) даёт
слишком большую дисперсию:
- **remainder stochastic sampling:** `rᵢ = F(Aᵢ)/F̄`; `⌊rᵢ⌋` копий гарантированно + дробная часть как
  вероятность ещё одной копии;
- **stochastic universal sampling (SUS):** один прогон рулетки с `N` равноудалёнными указателями вместо `N`
  независимых прогонов — снижает дисперсию выборки.

Также перечислены альтернативы (ранговый, турнирный, усечением) и **элитизм** — перенос нескольких лучших
особей без изменений, чтобы не терять лучшее найденное расписание между поколениями. Элитизм стоит включить
в демо явно, иначе лучшая найденная последовательность может быть случайно потеряна.

## 6. Сходимость и настройка — конкретные ориентиры параметров для демо

Из [[Сходимость и настройка генетического алгоритма]] — лекционные ориентиры гиперпараметров, полезные как
стартовая точка для демо-программы (подлежат проверке экспериментально на конкретных `n`, `H`):

| Параметр | Ориентир |
|---|---|
| `Pc` (вероятность кроссовера) | обычно 80–95%, иногда ~60% |
| `Pm` (вероятность мутации) | ~0.5–1% |
| `N` (размер популяции) | часто 20–30, для сложных задач 50–100 |

Признаки проблем, полезные как чек-лист при отладке демо: одинаковые хромосомы при плохом результате →
преждевременная сходимость; нет прогресса при высоком разнообразии → слабое давление отбора; частые
недопустимые потомки → оператор не согласован с кодировкой (см. §3); потеря лучшего решения → нет элитизма.

Также даёт таблицу сравнения ГА с полным перебором и градиентным методом — полезно для слайда
"почему ГА, а не другой метод" (дополняет аргумент через правило Смита/WSPT из `research_notes.md` §0,
который специфичен для *этой* задачи, тогда как таблица конспекта — общий аргумент).

## 7. Модели эволюции — материал для теоретической части презентации

[[Модели эволюции в генетических алгоритмах]] описывает 4 классические модели (Дарвин — базовый цикл;
Ламарк — наследование приобретённых признаков, соответствует гибридному ГА с локальным поиском, см. §8;
де Фриз — катастрофы и изоляция подпопуляций, соответствует островной модели, см. §9; Поппер — мутация как
метод проб и ошибок, отбор как устранение ошибок). Хорошо для вводного теоретического слайда о
биологических аналогиях, на которых строится ГА — не привязано к конкретной модели планирования, общий
теоретический фон курса.

## 8. Модификации ГА — материал для "дальнейшего развития" / сравнения

[[Модификации генетических алгоритмов]]: Genitor (steady-state, потомок заменяет худшую особь по рангу,
без ожидания целого поколения), CHC (агрессивный отбор + запрет скрещивания слишком похожих родителей +
"катастрофическая" мутация при потере разнообразия), гибридный ГА (локальный hill climbing поверх
потомков — ламарковская интерпретация), GAVaPS (переменный размер популяции, срок жизни особи зависит от
приспособленности). Полезно как раздел "что можно улучшить дальше", если демо будет расширяться за пределы
базового ГА.

## 9. Параллельные ГА — для раздела "future work"

[[Параллельные генетические алгоритмы]]: параллельное формирование поколения при турнирном отборе (`N/2`
независимых процессов) и островная модель с миграцией (топология кольцо/полный граф; пример: 1600 особей →
16 островов по 100, обмен каждые 5 поколений). Не требуется для базового демо на одном процессоре
(проект — про планирование на одном CPU, а не про распараллеливание самого ГА), но естественное направление
для "future work" слайда, тем более что тема курса — процессор и параллелизм.
