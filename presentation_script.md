# Содержание презентации: ГА для планирования процессов на одном процессоре

Визуальный план 13 слайдов, синхронизированный с речью из `speech.md`. На слайды выносятся только опорные
понятия, формулы, схемы и числа; полный рассказ остаётся у докладчика. Ориентировочная длительность —
18-22 минуты. Слайд 12 можно пропустить, если время ограничено.

## Общие принципы

- Один слайд — одна основная мысль.
- Не более 3-5 коротких текстовых блоков на слайде.
- Процессы `P1`, `P2`, `P3` обозначать одними и теми же цветами на всех схемах.
- CPU показывать сплошными цветными блоками, I/O — более светлыми или штрихованными продолжениями.
- Формулы не расшифровывать абзацами: смысл обозначений показывать стрелками и подписями.
- Анимацию использовать только для последовательного появления этапов, квантов или поколений.

## Слайд 2. Проблема планирования процессов

**Композиция:** в центре процессор, к которому слева подходят несколько процессов. Справа от процессора —
временная шкала одного процесса с чередованием цветных `CPU burst` и штрихованных `I/O burst`. Пока один
процесс находится на I/O, другой занимает CPU; это показать двумя синхронизированными дорожками.

Внизу — один короткий вопрос, который визуально связывает процессы с процессором.

**Текст на слайде:**

- `1 CPU → 1 процесс в каждый момент`
- `CPU burst`
- `I/O burst`
- `Кому отдать следующий квант?`

## Слайд 3. Классические алгоритмы

**Композиция:** верхняя треть — четыре компактные карточки с названием, пиктограммой и одним преимуществом
или ограничением:

- FCFS: очередь; подпись `просто → эффект конвоя`.
- SJF: короткая полоса первой; подпись `быстро для коротких → голодание`.
- Round Robin: круговая стрелка; подпись `справедливо → зависит от кванта`.
- Priority: флажки разной высоты; подпись `важные раньше → голодание`.

Нижняя часть — числовой пример. Слева показать три цветные карточки процессов:
`P1: p=8, q=2`, `P2: p=2, q=3`, `P3: p=5, q=1`. По центру разместить четыре мини-диаграммы Ганта с
порядком выполнения. Справа — вертикальный рейтинг результатов, где меньший `F` расположен выше и
подсвечен.

**Текст на слайде:**

- `FCFS: P1 → P2 → P3` / `F=61`
- `RR, квант 2` / `F=55`
- `SJF: P2 → P3 → P1` / `F=43`
- `Priority: P2 → P1 → P3` / `F=41`
- `Ни один не учитывает одновременно приоритет и I/O`

## Слайд 4. Планирование в реальных ОС

**Композиция:** четыре равные колонки с логотипами ОС. В каждой — название механизма и одна визуальная
метафора. Не описывать историю планировщика предложениями; версии и годы показать маленькими метками.

- Linux: шкала `CFS → EEVDF`, рядом виртуальный дедлайн.
- Windows: лестница из 32 уровней и стрелка временного повышения после I/O.
- macOS: четыре уровня QoS, преобразующиеся в приоритеты ядра.
- Android: энергоэффективное и производительное ядра, между которыми размещается задача.

Внизу — общая ось компромиссов: `справедливость — отзывчивость — энергия`.

**Текст на слайде:**

- `Linux: CFS → EEVDF` / `ядро 6.6, 2023`
- `Windows: 32 уровня + I/O boost`
- `macOS: QoS → приоритет`
- `Android: EAS → экономия энергии`
- `Нет универсального планировщика`

## Слайд 5. Модель проекта

**Композиция:** слева показать несколько карточек процессов. В каждой карточке три параметра с
пиктограммами: CPU, I/O и флаг приоритета. В центре — расписание `x` как цветная последовательность
квантов на шкале от `1` до `H`. Для одного процесса стрелкой отметить последний
CPU-квант `Eᵢ`, затем штрихованный участок I/O до `Cᵢ`.

Справа или внизу крупно разместить три основные формулы. Обозначения связать со схемой тонкими стрелками,
не добавляя отдельный текстовый словарь.

**Текст на слайде:**

- `Pᵢ = (pᵢ, oᵢ, qᵢ)`
- `H = Σpᵢ`
- `Cᵢ = Eᵢ + oᵢ`
- `F(x) = ΣqᵢCᵢ → min`

## Слайд 6. Зачем здесь генетический алгоритм

**Композиция:** разделить слайд на две половины.

Слева — что известно о задаче: это классическая `1||ΣwⱼCⱼ`, у неё есть точное решение. Показать карточки
процессов из примера, вычисленные отношения `pᵢ/qᵢ`, их сортировку и итоговую диаграмму Ганта
`P2 → P1 → P3`. Рядом поставить отметку точного решения.

Справа — что меняет ввод-вывод: `F(x) = ΣqᵢEᵢ + Σqᵢoᵢ`, второе слагаемое — константа, порядок процессов не
меняется (пример: `o₂=3` → `F = 41 + 9 = 50`, порядок тот же). Ниже — честный ответ на вопрос «зачем тогда
ГА»: правило Смита служит точным эталоном для проверки ГА, а сам ГА не опирается на структуру целевой
функции и переносится на усложнённые постановки, где точного правила нет, а перебор растёт как `n!`.

**Текст на слайде:**

- `1||ΣwⱼCⱼ — правило Смита / WSPT`
- `Сортировка по pᵢ/qᵢ`
- `P2 (0,67) → P1 (4) → P3 (5)`
- `F=41 — точный оптимум`
- `I/O: F = ΣqᵢEᵢ + Σqᵢoᵢ — константа, порядок не меняется`
- `ГА: не зависит от структуры F; Смит и перебор — эталон`

## Слайд 7. Жизненный цикл ГА

**Композиция:** большая кольцевая схема из шести этапов. Для каждого этапа использовать пиктограмму и не
более двух слов. В центре кольца — поколение `k`, после полного круга оно меняется на `k+1`. Рядом
небольшой график, на котором качество лучшей особи постепенно растёт.

В нижней части — две короткие колонки `Плюсы` и `Ограничения`, по два пункта без пояснений.

**Текст на слайде:**

- `Популяция → Оценка → Родители → Кроссовер → Мутация → Отбор`
- `Плюсы: без производных; параллельный поиск`
- `Ограничения: нет гарантии оптимума; важны параметры`

## Слайд 8. От расписания к особи

**Композиция:** верхняя половина показывает преобразование параметров процессов в хромосому.

1. Три карточки: `p₁=2`, `p₂=2`, `p₃=1`.
2. Мультимножество квантов: `1 1 2 2 3`.
3. Значок перемешивания.
4. Хромосома (генотип): `1 1 2 3 2`.

Одинаковые номера выделить одинаковыми цветами. Под хромосомой явно подписать: хромосома и есть расписание
(`xₜ = i` — в квант `t` работает процесс `i`); процесс может занимать несмежные позиции.

Нижняя половина — небольшая рулетка из нескольких особей: больший сектор соответствует большему fitness.
Справа разместить формулу приспособленности и короткую стрелку `F↓ → fitness↑`.

**Текст на слайде:**

- `Особь = расписание по квантам, длина H`
- `Процесс i встречается ровно pᵢ раз`
- `Перемешивание → допустимая особь`
- `fitness(x) = 1 / (1 + F(x))`
- `Pr(xʲ) = fitness(xʲ) / Σfitness(xᵏ)`

## Слайд 9. Кроссовер и мутация

**Композиция:** два вертикальных блока с разным визуальным акцентом.

Слева сначала показать неудачный одноточечный кроссовер: два родителя, обмен хвостами и красный потомок,
в котором нарушено число вхождений процесса. Ниже — GOX: выделенный сегмент копируется из первого
родителя, пустые позиции последовательно заполняются допустимыми элементами второго. У итогового потомка
поставить зелёную отметку.

Справа — одна исходная хромосома и три небольших преобразования: swap, insertion и reversal. Под ними
показать неизменившийся счётчик значений, например `1×2, 2×2, 3×1`.

**Текст на слайде:**

- `Обычный кроссовер → недопустимый потомок`
- `GOX → сохраняет число вхождений`
- `Swap / insertion / reversal`
- `Перестановка генов → допустимость сохраняется`

## Слайд 10. Демонстрация и результаты

**Композиция:** использовать визуализацию из `demo/convergence_chart.html`. Слева или сверху — график
сходимости по 400 поколениям: лучшая особь, среднее по популяции и пунктир "точный оптимум = 243". Точку
поколения 345 выделить подписью (ГА находит оптимум поздно: на 20 запусках с разными seed оптимум нашли 10). Справа или
снизу — горизонтальная столбчатая диаграмма сравнения алгоритмов, отсортированная по возрастанию `F(x)`.

Параметры запуска разместить одной компактной строкой над графиком или в четырёх небольших бейджах. Не
выводить найденную хромосому целиком: она перегружает слайд и не помогает сравнению.

В углу добавить отдельную зелёную карточку валидации: точный оптимум найден полным перебором всех `6!`
порядков (`bruteForceOptimal` в `demo/scheduler_ga.js`) и совпадает с правилом Смита; перебор годится только
при маленьком `n`, а ГА не зависит от структуры `F` (слайд 6).

**Текст на слайде:**

- `N=60` / `400 поколений` / `Pc=0,85` / `Pm=0,2` / `элитизм=2`
- `ГА: 243`
- `Точный оптимум (перебор 6!): 243`
- `WSPT (правило Смита): 243`
- `Priority: 252`
- `SJF: 260`
- `Round Robin: 363`
- `FCFS: 386`
- `Проверка: oᵢ=0 → ГА = WSPT = перебор = 167 (разница с I/O = Σqᵢoᵢ = 76)`
